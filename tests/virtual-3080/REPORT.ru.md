# Отчёт: Local AI Lab на виртуальной RTX 3080

Дата: 10.10.2026 · версия системы: 1.4.0 · автор системы: Serhii Khomenko

## 1. Что проверялось

Цель — убедиться, что программное обеспечение сервера правильно работает с видеокартой, не имея самой видеокарты. Для этого на Linux-машине с Docker была собрана **виртуальная RTX 3080 (10 ГБ)**, а система установлена с нуля по инструкции для пользователя и прогнана по всем частям, которые работают с GPU.

Настоящих моделей нет: ответы — заготовленные тексты, все числа условные. Проверялась **работа сервера**, а не качество моделей.

## 2. Как устроена виртуальная видеокарта

| Что в настоящей системе | Чем заменено | Как ведёт себя |
|---|---|---|
| Драйвер NVIDIA для Docker | `nvidia-container-runtime-hook` | `--gpus all` и `gpus: all` работают; в каждый контейнер с GPU копируется виртуальная `nvidia-smi` |
| `nvidia-smi` | `nvidia-smi` | «NVIDIA GeForce RTX 3080», 10240 MiB; занятая память, загрузка, мощность и температура берутся у работающих виртуальных моделей |
| llama.cpp (`llama-server`, `llama-bench`) и llama-swap | `fake_llama.py` в образе `local/ai-server-llama-swap:260` | те же пути и API; видеопамять = размер файла + кэш контекста (f16 / q8 / q4); модель, которая не помещается, падает с «cudaMalloc failed: out of memory», как настоящая; запрос длится 1–4 с с загрузкой GPU 97 % |
| Файлы моделей `.gguf` | `make_models.py` | 32 разреженных файла правдоподобного размера (на диске ~230 КБ) |

Всё остальное — консоль, шлюз, раннер тестов, сборщик отчёта, SQLite-архив, страница хода тестов, Gitea и версионер — **настоящий код системы без изменений**.

## 3. Развёртывание с нуля (по шагам)

Исходник — свежий ZIP репозитория, как его скачивает пользователь. Шаги из `tests/virtual-3080/README.md`; шаги 2–8 — те же, что в README для пользователя.

| № | Команда | Результат |
|---|---|---|
| 1 | виртуальный драйвер в `/usr/local/bin`, перезапуск Docker | `docker run --gpus all … nvidia-smi` печатает RTX 3080 |
| 2 | `install.py doctor` | Docker 29.8.2, Compose 5.6.0, порты 8766 / 8080 / 8765 / 3010 / 2222 свободны — всё `[ok]` |
| 3 | `install.py init` | `.env`, папки, заглушки, сеть `ai-net`, том `llm-models-fast`; конфигурация Compose верна |
| 4 | `MODEL_DIR` в `.env`, виртуальный образ шлюза, `make_models.py` | 32 файла моделей в томе |
| 5 | `install.py build --no-gpu` | собраны образы консоли и версионера |
| 6 | `install.py up` | запущены 6 сервисов |
| 7 | `install.py git` | создан Gitea-пользователь `reports-admin`, репозиторий `model-test-reports`, запущен версионер |
| 8 | `install.py verify` | **14 из 14 `[ok]`**: консоль, API, каталог моделей, отчёт, лицензии, версия, шлюз, Gitea, все 6 контейнеров здоровы |
| 9 | `docker compose --profile bench up -d --build bench-runner` | раннер тестов запущен |

Установщик для Windows (`install.ps1`, в том числе новый шаг `git`) проверен в PowerShell: первый запуск и повторный (ничего не ломает) — `ok`.

## 4. Результаты

### 4.1. Консоль (http://localhost:8766/)

- Видеокарта: «NVIDIA GeForce RTX 3080», 10240 MiB; каталог — 14 профилей (LLM, эмбеддинги, зрение).
- «Старт» MiniCPM5-2B-Q8_0 → в памяти 3324 / 10240 MiB, 36,7 W; карточка показывает контекст 131 072, скорость чтения 4500 и генерации 200 ток/с, параметры запуска.
- Диалог: модель отвечает через шлюз. «Стоп» → видеопамять освобождена.
- Ошибок JavaScript нет ни на одной странице (консоль, отчёт, ход тестов в видах A и C, светлая и тёмная тема).

### 4.2. Общий тест — 23 модели

Каждая модель: загрузка, скорость на контексте 8K, пик видеопамяти, задачи качества, проверка контекста 16K–64K. Все 23 прошли примерно за 0,4 мин каждая, ошибок нет.

| Модель | Диск, ГБ | VRAM пик 8K, МиБ | Генерация, ток/с |
|---|---|---|---|
| MiniCPM5-2B-Q4 | 1,2 | 1581 | 185,6 |
| Spark-X2.5-4B-Q8 | 4,25 | 4547 | 113,5 |
| Qwen3.5-9B | 6,3 | 6646 | 76,6 |
| Gemma-3-12B | 7,2 | 7590 | 67,0 |
| Gemma-4-12B | 8,05 | 8401 | 60,0 |

Видеопамять растёт с размером модели и окна (Qwen3.5-9B: 6598 МиБ на 8K → 8404 МиБ на 64K) — раннер получает её из `nvidia-smi` внутри своего контейнера.

### 4.3. Немецкий язык — 23 модели

Этап прошёл без сбоев. Счёт 0 из 30 у всех ожидаем: заготовленные ответы неверны, и проверка их **не засчитывает**.

### 4.4. Максимальный стабильный контекст — главный тест видеокарты

Тест ищет самое большое окно, при котором модель запускается, находит 3 из 3 спрятанных фактов, не теряет скорость, по-настоящему нагружает GPU и оставляет ≥ 250 МиБ свободными.

| Модель | f16 | q8 | q4 | Итог |
|---|---|---|---|---|
| MiniCPM5-2B-Q8 | 131 072 — 3324 МиБ | — | — | **131 072, f16** |
| Qwen3.5-9B | 98 304 — 9484 МиБ; 131 072 — не запустилась | 196 608 — 9670 МиБ; 262 144 — не запустилась | 262 144 — 8700 МиБ | **262 144, q4** |
| Gemma-4-12B | 65 536 — **отбракована: «мало видеопамяти: пик 9998 МиБ»** | 98 304 — 9434 МиБ; 131 072 — не запустилась | 131 072 — 8787 МиБ | **131 072, q4** |

Работают все ветви логики: поиск окна делением пополам, отказ при нехватке видеопамяти, защита от работы впритык к 10 ГБ, выбор типа кэша.

### 4.5. Итоговая проверка через шлюз (soak)

Шлюз сам загружает и меняет модели. Проверка: 3 заполнения окна на 93–95 %, длинная генерация, картинка для моделей со зрением, эмбеддинги. Во время работы снимаются видеопамять, загрузка и мощность GPU.

| Профиль | Окно | Факты | VRAM пик | GPU пик | Итог |
|---|---|---|---|---|---|
| MiniCPM5-2B-Q8_0 | 131 072 | 3/3 ×3 | 3324 МиБ | 97 %, 309 W | замечание: длинный ответ — 72 токена |
| Qwen3-VL-8B (зрение) | 65 536 | 3/3 ×3 | 6282 МиБ | 97 % | замечания: короткий ответ; картинка не распознана |

Замечания ожидаемы: виртуальная модель отвечает короткой заготовкой и не видит картинку. Важно, что сервер **поймал** обе проблемы и записал их в результат.

### 4.6. Отчёт, архив и версии

- Отчёт (http://localhost:8766/report/) сам показывает все 23 модели со свежими результатами.
- SQLite-архив `results-db/llm-results.sqlite`: 160 строк сырых данных, 94 записи истории, оценки 23 моделей.
- Ход тестов (http://localhost:8766/report/progress.html): этапы, текущая модель, оставшееся время, журнал.
- Gitea (http://localhost:3010/): версионер сохранял новую версию каждую минуту во время прогона — теги v0001…v0029.

## 5. Найденные и исправленные ошибки

**В системе** (сказались бы на настоящей RTX 3080):

1. У контейнера раннера тестов не было доступа к видеокарте (`gpus: all` в `docker-compose.yml`). На настоящей карте пик видеопамяти и загрузка GPU во всех тестах записались бы как 0, а тест контекста отбраковал бы все прогоны.
2. Версионер при пустом токене заменял `***` каждую букву сообщения об ошибке — текст ошибки было не прочитать.
3. `setup_git.py` падал, если в системе нет `ssh-keygen`; теперь SSH-ключ необязателен.
4. В установщиках не было шага настройки Git — его приходилось запускать отдельным скриптом. Добавлен шаг `git` (`install.ps1 git` / `install.py git`); он входит в `all`.

**В виртуальной видеокарте** (исправлено, пока её отлаживал):

- запросы шли слишком быстро (0,05 с), и замеры раз в 0,5 с не видели загрузку GPU — теперь запрос длится 1–4 с;
- не читались многострочные команды в `config/llama-swap.yaml` (профили эмбеддингов);
- размер модели не брался из имени папки (Mistral-Nemo-12B считалась моделью 4B);
- исправлены оценка числа токенов, регистр «12b» и размер головы MTP.

## 6. Что эта проверка не покрывает

- настоящие скорость и качество моделей — они измеряются только на настоящей видеокарте;
- генерацию картинок и видео (отдельный проект Video Studio);
- Docker Desktop с WSL 2 на Windows. Установщик для Windows проверен в PowerShell, но на Windows-машине не запускался.

## 7. Нужен ли ИИ-ассистент для установки

**Нет.** Система ставится шестью командами по одной (`doctor`, `init`, `build`, `up`, `git`, `verify`). Нужно уметь вставить команду в PowerShell и поправить одну строку `.env` в Блокноте. На Windows не нужны ни Python, ни Git — только Docker Desktop.

Ассистент полезен, но не обязателен. Он может:
- выполнить установку за вас;
- подобрать модели под видеокарту;
- следить за долгим прогоном тестов и повторять сомнительные замеры;
- разбирать журналы при сбоях.

Подходит только ассистент, **который запускает команды на этом компьютере** (Claude Code, агент Codex и подобные): ему дают `PROMPT_FOR_AI.md`. Обычный чат в браузере ничего не установит, но объяснит ошибку по её тексту.

Всё это написано в README (RU / EN / DE), разделы «Сам или с ИИ-ассистентом?» и «После установки: чем пользоваться».

## 8. Как повторить

`tests/virtual-3080/README.md` — те же шаги на любой Linux-машине с Docker и без видеокарты NVIDIA. **Не ставить на компьютер с настоящей видеокартой NVIDIA**: виртуальный драйвер подменяет настоящий.
