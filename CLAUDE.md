# Claude Code: working instructions

The same instructions as `AGENTS.md` (this file is read automatically by Claude Code). In short:

- **You install, start and supervise this server for the human.** The server works without you; you are the operator and the reviewer of the tests.
- Read `docs/AI_OPERATOR.en.md`, `docs/INSTALL.en.md`, `docs/API.md`, `docs/RESULTS_FORMAT.md`, `docs/METHODOLOGY.en.md`.
- Install with `python scripts/install.py doctor | init | build | up | git | verify` (`--no-gpu` on a PC without an NVIDIA GPU; `doctor --pull` downloads 5.6 GB, ask first); on the owner's Windows PC, which has only Docker Desktop, use `scripts\install.ps1` with the same steps (`-NoGpu`, `-Pull`); ask the human for `MODEL_DIR`, the network address and, for LAN use, the console password (`AI_CONSOLE_PASSWORD`); start with one small model.
- One model in video memory at a time; test results are appended to `bench_results/results_*.jsonl` with progress in `bench_results/<stage>.log`; check every result for plausibility and repeat suspicious runs before you report.
- Ask before deleting, opening ports, downloading more than 1 GB or publishing. Never expose the console or gateway to the internet, never write secrets into Git, never rewrite earlier results.
- Console `POST` calls need `Content-Type: application/json`; never weaken `console/security.py` or the fixed `docker exec` form.
- Changing code: standard library only in the console, keep RU/EN/DE complete (`node scripts/check_i18n.js de`), run `python -m unittest discover -s tests`, `python scripts/build_site.py --style <homensai-style>` after changing Markdown (pages in `site/` are generated by the style core's site builder; every page in EN/RU/DE) and `python scripts/make_manifest.py --check`, bump `VERSION` and `CHANGELOG.md` for a release.

Full text: [AGENTS.md](AGENTS.md).

## Required preflight and prompt caching (owner instruction, 2026-11-12, updated with measurements)
Read **all of AGENTS.md** and its AI context/caching policy before substantive work. Inventory the project and current state; fully trace task-relevant code/docs; reuse a compact context map; targeted reads, trimmed tool output (`head`/`tail`/`cut`), no pasting of whole repositories, logs or JSON.
**Prompt caching is the main cost lever, always on.** Claude Code: user settings `~/.claude/settings.json` must contain `"promptCacheTtl": "1h"` and `"subagentPromptCacheTtl": "1h"` (documented settings; subagents otherwise get 5 min and every wait > 5 min rewrites their whole context). Do not switch model, effort or fast mode mid-session; continue a running agent (SendMessage) or fork instead of starting a fresh one; long commands in the background. Direct Claude Messages API: stable shared material first with `cache_control` at the end of it, the changing question after; cache only when the prefix is read again (1 task: no marks; 2+ tasks starting together: 5m + one `max_tokens: 0` pre-warm; 3+ queued: 1h); every report states **with cache $X vs old way $Y, saved $Z, ×K** from `cache_creation_input_tokens` / `cache_read_input_tokens`.
