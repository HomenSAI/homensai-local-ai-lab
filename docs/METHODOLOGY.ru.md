# Как получены результаты

Другие языки: [English](METHODOLOGY.en.md) · [Deutsch](METHODOLOGY.de.md) · Цифры: [results-public/RESULTS.md](../results-public/RESULTS.md)

## Цепочка: ядро → супервизор → результаты → этот репозиторий

```
 ядро сервера                      супервизор                          результаты                        публикация
 шлюз (llama-swap + llama.cpp)     Claude (Anthropic, сессии Claude    bench_results/results*.jsonl      этот репозиторий:
 консоль, сборщик отчётов,         Code на этом же ПК, по поручению    → сборщик отчётов → архив SQLite  код, документация, results-public/
 версионер Git                     автора)                             + живой отчёт                     (теги Git v0001 … final-<дата>)
 [этот репозиторий, код]           готовит, запускает и проверяет      → версии в локальном Gitea
                                   тесты
```

1. **Ядро сервера** — код этого репозитория: шлюз llama-swap на зафиксированных сборках llama.cpp, консоль, сборщик отчётов (объединяет файлы результатов, не удаляя старые), версионер, который сохраняет каждую версию отчёта в Git. Само по себе оно ничего не оценивает.
2. **Супервизор** — Claude, использованный как помощник по программированию и эксплуатации на ПК автора (см. [AI_OPERATOR.ru.md](AI_OPERATOR.ru.md)). По поручению автора он написал и доработал скрипты тестов, запускал их на шлюзе по одной модели, следил за прогонами, повторял подозрительные, разбирал файлы результатов и писал отчёты и выводы.
3. **Результаты** — одна JSON-строка на модель и тест в `bench_results/results*.jsonl` (формат: [RESULTS_FORMAT.ru.md](RESULTS_FORMAT.ru.md)); сборщик отчёта превращает их в живой отчёт и архив SQLite; версионер сохраняет каждое изменение в локальный Gitea.
4. **Публикация** — [results-public/](../results-public/) генерируется из живых данных скриптом `scripts/make_public_results.py` (без сырых промптов и ответов) и публикуется вместе с кодом.

## Правила автора (они определяют каждую цифру)

- **Только GPU.** Модель, которая работает лишь с переливом в RAM/CPU (1–3 токена/с), рабочей не считается.
- **Устойчивый GPU-контекст не меньше 64K** — условие участия в поздних этапах. Первые этапы прошли 23 модели; 8 не дотянули до 64K на GPU и сняты с поздних тестов (они есть в таблице с причиной); 15 допущены.
- **Одна модель в видеопамяти за раз**; шлюз переключает модели, супервизор никогда не запускает две GPU-задачи вместе.
- **Ничего не перезаписывается**: повторный тест добавляет новую строку; архив и Git хранят прежние значения.

## Что измерялось (этапы в порядке запуска)

| Этап | Что измеряет |
|---|---|
| Общий тест (контекст 8K) | русский язык, логика, код, следование инструкциям, зрение; скорость чтения и генерации, пик видеопамяти |
| Немецкий: пассив | 30 форм немецкого пассива, проверка точного ответа |
| Максимальный стабильный контекст | самое большое окно, при котором сервер стартует, находит 3 из 3 спрятанных фактов на 80% заполнения и держит скорость; KV-кэш на GPU пробовался как f16, q8 и q4 |
| Ускорители и эмбеддинги | скорость с MTP, DFlash или черновой моделью и без них (14 профилей); две модели эмбеддингов |
| Математика и физика, 11 класс | 40 сгенерированных задач (20 + 20) с вычисленным ответом; часть моделей также с включёнными размышлениями |
| Надёжность (soak) | каждый профиль шлюза проходит серию шагов: запуск, ответы на разном контексте, пик видеопамяти, свободная память хоста |
| Код, 20 задач | 20 задач по программированию трёх уровней сложности, проверка запуском тестов |
| Химия, 11 класс | 10 задач с вычисленным ответом |
| Итоговые профили и отчёт | измеренные контексты переносятся в профили шлюза и проверяются |

Окружение: NVIDIA GeForce RTX 3080 (10 ГБ), Windows 10 + Docker Desktop (WSL2), llama.cpp коммит `81bc6b83f827df746eb129235488d325c49cae52`, форк PrismML `adfffbe41b2cabcd51fff326ab045662265062bb` (только модель Bonsai), llama-swap v260. Прогоны шли с 2026-09-30 по 2026-10-06.

## Ограничения, которые нужно знать

- **Одна машина, небольшие наборы задач.** 10–40 задач на тест: разница в несколько процентов — шум. Таблицы — ориентир, а не рейтинг качества моделей.
- **Тесты писал и проверял ИИ-супервизор.** В чекере может быть ошибка; супервизор искал задачи, которые проваливают все модели (признак неверного чекера), и повторял подозрительные прогоны, но каждый ответ человек не перепроверял.
- **Задачи сгенерированы или написаны нами**, а не скопированы из публичных бенчмарков; поэтому они несравнимы с опубликованными таблицами лидеров.
- **Настройки важны**: квантование, размер контекста, тип KV-кэша и режим размышлений входят в каждый результат; они сохранены в строках и в `config/llama-swap.yaml`.
- **Сами скрипты бенчмарка в этот релиз не входят** (в них ещё есть пути конкретной машины); входят файлы результатов, их формат и план этапов, так что любой инструмент может выдавать сопоставимые строки.

## Как привязать копию репозитория к результатам

Если вы публикуете форк, впишите его адрес в `.env` как `PUBLIC_REPO_URL=https://github.com/HomenSAI/homensai-local-ai-lab`: в подвалах консоли и отчёта появится ссылка «GitHub», а консоль вернёт её в `/api/version`.
