Заметки о проверке

  • Bonsai — GGUF v3, архитектура qwen35, file_type 143. Его байты совпадают с контрольной суммой LFS на Hub. PTQ1_0 должен работать в среде выполнения PrismML и не должен направляться через стандартный llama.cpp.
  • Выбранный файл Qwen MTP — GGUF v3, архитектура qwen35, 442 тензора и 33 блока. Метаданные содержат nextn_predict_layers=1 и четыре тензора .nextn.*. Имеющийся файл Q5_K_S — без MTP и остаётся нетронутым; его новый профиль qwen-q5 — явный сервис для сравнения.
  • Проектор Qwen3.5 — GGUF v3 clip с метаданными зрения/проектора Qwen3VL.
  • GGUF MiniCPM — Q8_0, 381 тензор и 42 блока. Контекст в метаданных — 131072; контексты профилей по-прежнему определяются бенчмарками.
  • DSpark — отдельная голова DFlash в формате GGUF с 5 блоками и размером блока 7. Она загружается в зафиксированной среде выполнения; принятие при n=4 измерено, но в точном ответе проверки здравого смысла на короткий ответ пропало обязательное пояснение, поэтому по умолчанию остаётся MiniCPM без DSpark. n=7 работал медленнее.
  • GGUF Spark — v3, архитектура spark2_5, file_type 7. Зафиксированная среда выполнения upstream новее слияния нативной поддержки в b10828.
  • Байты и размер Whisper совпадают с официальным объектом LFS на Hub в записанной ревизии.
  • Диффузионная модель Qwen Image, энкодер Qwen3-VL, mmproj для редактирования и VAE Qwen Image 2.1 имеют точные размеры и локально вычисленные значения SHA256, совпадающие с локальным etag Hugging Face каждого зафиксированного файла; ревизии репозиториев тоже проверяются. Заголовок диффузионного GGUF — v3, в нём 265 дескрипторов тензоров и ноль записей метаданных; дескрипторы используют имена model.diffusion_model.*, поэтому значение general.architecture не заявляется. Три остальных файла содержат записанные метаданные.
  • Qwen-Image-2.1 — диффузионный трансформер, а не чат- или текстовая модель. llama.cpp не выполняет её архитектуру qwen_image. Основные языковые модели остаются на llama.cpp; профиль Qwen Image использует зафиксированный stable-diffusion.cpp внутри этого же проекта Docker. Тест 1024×1024/20 шагов прошёл с --params-backend diffusion=disk, выгрузкой на CPU и тайловым VAE; результат и пиковая телеметрия лежат в media/images/.

Измеренные рабочие настройки (RTX 3080 10 GiB)

  • Qwen3.5 MTP n-max=2: среднее по трём повторам 93.4 tok/s против 79.8 tok/s без MTP (+17%); та же проверка содержания с фиксированным seed тоже пройдена, с принятием черновика 69% и пиком 8678 MiB. n=4 дал в среднем 88.3 tok/s, n=6 — 62.2 tok/s. Оставить n=2 при контексте 65536.
  • MiniCPM: DSpark OFF. Прогон n=4 с тремя повторами дал в среднем около 155 tok/s против 143 tok/s без DSpark, но в его проверке содержания на том же запросе пропало запрошенное пояснение, а пример faulthandler.dump_traceback_limit оказался неверным. n=7 дал в среднем около 131 tok/s. Сохранить рабочий профиль одной модели; контекст в парном режиме — 8192.
  • Spark: одиночный профиль F16 KV / контекст 65536; парный профиль Q8_0 KV / 16384. Средние по трём повторам — около 81.1 tok/s (F16) и 75.2 tok/s (Q8_0); Q8_0 оставлен только ради запаса памяти для пары одновременно загруженных моделей. Для обычных запросов API/UI задавайте enable_thinking=false, потому что с включёнными размышлениями модель в пределах лимита теста не вернула видимого пользователю содержимого.
  • Bonsai: только PrismML, контекст 32768 пройден с пиком по выборке 8488 MiB (~1.7 GiB свободно). Остаётся экспериментальной до ручного сравнения качества ответов.
  • Qwen Vision: контекст 32768 пройден отдельно; пик 8143 MiB. Whisper — только по запросу.

Условие для двух одновременно загруженных моделей

Одновременно могут быть загружены только MiniCPM5 + Spark. Проверенная конфигурация 8192 + 16384 со Spark Q8_0 KV прошла: в простое суммарно 8289 MiB VRAM (1951 MiB свободно); контролируемый одновременный пик 8300 MiB (1940 MiB свободно), без ошибок OOM/CUDA; изменение последовательной пропускной способности — в пределах 1% для каждой модели. Парный режим включён, но по умолчанию запросы должны выполняться последовательно. Профили одной модели сохраняют свои измеренные настройки KV.

Все семь профилей входят в единственную группу llama-swap с swap: true, exclusive: true. globalTTL=900 выгружает простаивающий бэкенд через 15 минут. У шлюза нет списка предзагрузки, поэтому после запуска и перезапуска его состояние — ACTIVE MODEL=NONE. Диффузия Qwen Image и Whisper STT не реализуют chat completions и не входят в /v1/models.
